  - 페이지 지우기는 확인 창 없이 바로 지우고 Ctrl+Z로 같은 자리에 되돌린다. 보던 페이지를 지우면 옆 페이지로 옮겨 간다.
- 미완료/다음 작업: 커밋·push(사용자 요청 시). 마스크, Grid 레이아웃, 컴포넌트 속성.

- 결정 사항:
  - React 출력: 절대 위치 자식의 left·top을 부모 지역 좌표로 계산하고, 자식 CSS 변환은 부모에 대한 상대 행렬로 쓴다. 전에는 페이지 좌표 차이와 절대 행렬을 써서 부모 div의 회전·반전이 두 번 적용됐다. 뒤집은 프레임이 뒤집히지 않은 모양으로 나왔고, 회전한 프레임 안의 자식도 두 번 회전했다(회전 쪽은 이번 변경 전부터 있던 문제).
  - 오토 레이아웃: 부모에 대한 상대 행렬이 반전(대각 성분 ±1)뿐이면 회전으로 보지 않는다. 가로·세로 축이 그대로라 채우기·맞춤 크기를 유지한다. 전에는 뒤집은 채우기 자식이 고정으로 바뀌었다.
  - 뒤집기 정밀도: 반전은 위치를 0.01로 반올림하지 않고 부동소수 잔여값(1e-6)만 지운다. 소수 셋째 자리 좌표(210.333)도 두 번 뒤집으면 그대로 돌아온다. 회전은 그대로 0.01 단위다.
  - 거리 표시: 변이 맞닿은 도형(간격 0)을 떨어진 것으로 보고 선을 그리지 않는다. 전에는 겹친 것으로 보아 두 도형 너비만큼의 선이 나왔다.

## 2026-11-19 08:47 작업 내역
- 작업 내용: SVG 그림 붙여 넣기 실패 수정. 사용자가 준 테스트 자료(git 제외 `test` 폴더, 커밋하지 않음)를 앱에 넣어 보다가 SVG 32개가 모두 "The source image could not be decoded"로 실패하는 것을 찾았다.
- 변경 파일: `app\src\assets.ts`(`svgIntrinsicSize`, `readImageSize`), `app\src\App.tsx`(`pasteImageFile`), `app\tests\assets.test.ts`(신규).
- 결정 사항:
  - 원인: 그림 크기를 `createImageBitmap`으로 읽었는데, Chromium은 SVG를 이 함수로 해석하지 못한다. 10×10짜리 단순한 SVG도 실패했고, 같은 파일이 `<img>`로는 열렸다.
  - SVG 크기는 루트 `<svg>`의 width·height(단위 없음·px)에서 읽고, 없으면 viewBox, 한쪽만 있으면 viewBox 비율로 나머지를 정한다. 아무 크기도 없으면 100×100. 브라우저마다 크기 없는 SVG 기본값이 달라 직접 읽는다. PNG·JPG·GIF·WebP는 그대로 `createImageBitmap`을 쓴다.
  - 크기를 먼저 읽고 나서 그림을 저장소(IndexedDB)에 넣는다. 전에는 저장 뒤에 해석해서, 실패한 그림이 저장소에 남았다.
- 미완료/다음 작업: 커밋·push(사용자 요청 시).
- 이슈/특이사항:
  - `npm run typecheck`, `npm test`(실제 `.fig` 포함 166개 통과, 새 4개), `npm run build` 통과.
  - 브라우저 확인: 테스트 자료의 SVG 32개(아이콘 29개, 1920px 화면 3개)를 붙여 넣자 모두 들어가고 32개 모두 그려졌다. 크기는 파일에 적힌 값(예: 8.36×9.45, 1920×3556)과 같다. 전에는 32개 모두 실패했다.
  - 검증에 쓴 브라우저 localStorage와 추가된 그림 32개는 지웠다.
